# Changes

## 7.23.0-rc.14 - 2026-10-25 (laboratory candidate)

- **Advisor and Reviewer.** Two Codex skills and Claude commands share role-specific briefs and one consultation policy. The Orchestrator retains responsibility; advice uses the same provider natively, independent review another provider. Model selection is contextual, without an obligatory higher-ranked Advisor. Consultation does not authorize writes, publication or further delegation.
- **Reviewer fallback.** When the other provider is observably unavailable (quota blocked, failing doctor, or an infrastructure failure or timeout of this delivery's external review), a fresh native agent of the same harness reviews instead: new spawn without inherited conversation, never a fork or the Advisor instance, blind brief, any host model. Admission requires `--fallback`, records `independence: same_provider_fallback`, reuses the Reviewer slot only after an unavailable external attempt and allows one automatic fallback per delivery. Announced as a fallback with reduced independence.
- **Board projection.** `board --json` jobs carry `consult_role`, `consult_delivery` and `initiation`; a `consultations` block lists visible native admissions (role, model, state, stale, fallback, independence) and effective autonomy per visible session. Read-only; damaged consultation state yields `available: false` without hiding jobs. Consumed by Agents Monitor 3.2.0 to show Orchestrator, Advisor and Reviewer.
- **Autonomy toggle.** Default on, with session, future-default and all-session controls separate from the delegation hard off. Explicit requests remain possible while autonomy is off, without re-enabling it. Global changes invalidate earlier overrides. Queued automatic work is invalidated before launch; already started work continues unless cancellation is requested. Existing hard-off choices survive updates.
- **Admission and limits.** Cooperative native admit/start/finish, external role/delivery/initiative metadata, one automatic call per role per delivery, aggregate session/provider caps and concurrency across admitted natives and external jobs. Explicit retry preserves role/delivery and does not reset the toggle; a refused retry does not mutate its parent link. Legacy omitted initiative is automatic, avoiding an autonomy-off bypass; correctly classifying roles remains a principal obligation. Frozen, authorized model-evaluation executions declare explicit initiative. A native consultation left unfinished for two hours is marked stale and stops holding concurrency. Damaged consultation state blocks new admissions and automatic launches but no longer strands finalization or hard off; jobs already running from earlier versions are not cancelled by autonomy off.
- **Limits of enforcement.** Native spawn and cancellation remain host actions; CLI admission is not a universal host-tool block. No monetary ceiling, process telemetry, model superiority or human approval is inferred. State inspection and installation do not call providers. Installer migration adds both exact skill ignore rules and refuses tracked collisions.
- **Validation.** Deterministic admission/lifecycle and installation cases plus independent instruction scenarios cover explicit one-shot use, scope precedence, queue/preflight shutdown, retry integrity, budgets, role/provider relationships and authorization boundaries. Real host discovery, long-term cost and quality effects require observation after installation.

## 7.23.0-rc.11 - 2026-10-21 (laboratory candidate)

- **ONE-PAGE operation.** `/one-page` (Claude Code and Grok), skill `thinker-one-page` (Codex, implicit invocation allowed) and `harness/operations/one-page.md` build a one-page brief a colleague reads in two minutes: a two-sentence opening whose second sentence is the decision asked, an "at a glance" table (context, problem, opportunity, one or two reframes), an optional diagram, a lens table where each lens (business, product, design, technology) carries one refutable hypothesis, what would refute it and with whom, then optional next steps, data, connections and sources. It shows on screen first, keeps a draft in `drafts/one-page/` with reviewer notes in a sibling file that is never exported, and exports only on request to the host's document or page destination or to `output/one-page-<slug>/`. It never writes pages, log entries or the index.
- **Room filter.** Before writing, the agent asks whether it would read each line aloud with everyone named in the room, client included. Judgments about people, power readings, confidential or unofficial items, internal conflict and private conversations as a source of authority stay out; positions on the subject stated in a forum go in, attributed. Removing people and backstage must not remove substance: a page that turns generic goes back to the material.
- **Budget.** 420 words counted by `harness/scripts/one-page-count.sh` (before Sources, ignoring table syntax, checkboxes and diagram blocks), about 6–10 numbers, one fact in one place, and a cut order that never drops the reframe, the counterintuitive finding, the strongest critique of one's own material or the decision.
- **Calibration.** Four rounds on real consulting cases (commercial lead, discovery proposal, internal offer, client kickoff), judged blind by models from two providers against a page the user had approved (~370 words). Recurrent defects fixed in the playbook: too many numbers with different bases, wrong role for a person, report turned into fact, private conversation used to settle an internal debate, the closing decision drifting away from the opening. Moving hypotheses into the lens table cut about a fifth of the words without losing them.
- **Public-repo hygiene.** The README, `AGENTS.md` and two test fixtures no longer carry the maintainer's name, local path or employer domain.
- Unmeasured: how often a user edits the page before sharing it, and quality outside consulting work.

## 7.23.0-rc.10 - 2026-10-19 (laboratory candidate)

- **Ranked search.** `build-index.py search` now ranks with SQLite FTS5 BM25 (in-memory, rebuilt per call, `unicode61 remove_diacritics 2`) over title, summary, tags and body, weighted 3/2/1/1. Common Portuguese/English function words are dropped unless the query has nothing else; unquoted words of four or more characters match as prefixes, so a singular finds plurals; hyphenated or apostrophe words and quoted text are phrases; digits count. Output format, exit codes, `--all` and status badges are unchanged. `THINKER_SEARCH_ENGINE=legacy` restores the old ranking, which is also the automatic fallback when the local SQLite lacks FTS5. No index file, daemon or dependency; a call took about 0.2 s on a vault of a few hundred pages.
- **Search before grep.** `context.md` gains *Localizar paginas*: locate pages with `search` and 2–6 loose terms (names, central concept, a likely synonym in the other language); quotes only for exact phrases, `--all` only to narrow; grep for literal strings, confirmation or inside a chosen page; ranking suggests candidates, not truth or currency. `query.md`, `deep.md`, `CLAUDE.md`, `AGENTS.md` and the Grok rules point to it. Session transcripts showed agents almost never calling `search` and grepping instead.
- **Evaluation.** The change was decided by a pre-registered retrieval evaluation on one private vault: questions mined from real sessions plus synthetic direct and paraphrased questions, results pooled and judged blind by a model (0/1/2), nDCG@5 with paired bootstrap intervals. With loose terms for every method, the new ranking scored about +0.12 nDCG@5 over the previous search and +0.20 over a single grep pass; on real questions alone it tied the previous search (interval crossing zero) and beat grep. Most of the gain came from paraphrased questions and from typing the question as-is. Weights 3/2/1/1 are the combination evaluated, not a tuned optimum.
- **Embeddings: not now.** No question in the set was found only by meaning without shared words, so vector search had nothing to win here. That evidence is weak: the judge saw only title, summary and the first lines, and keywords chosen by an agent already carry vault vocabulary. Revisit if paraphrase misses show up in real use.
- Known limits: long hub pages are penalized relative to short pages that mention a stray query term; the threshold message that suggests evaluating FTS5 past 800 pages is now stale; FTS5 availability was verified on one macOS Python build only.
- Plan and results were reviewed blind by Astra (via the extension) and Fable (native agent with access to code and data); their objections — an unfair baseline, judgment merging, the weight mislabel — were fixed before release.

## 7.23.0-rc.9 - 2026-10-18 (laboratory candidate)

- **Automatic local signals.** `route`, `submit` and `retry` read the Codex rollouts at decision time, in memory, and use whichever is newer between that and the `--observe` cache; `route` still writes no state. The extra cost measured on the real vault was about 70 ms per call.
- **Claude half.** `delegation-indicator.py --claude-statusline` records the statusline's `rate_limits` (5 h and 7 d) in `quota-observation-claude.json`: no lock, atomic rename, only when values change or every 5 minutes, and only when the state area already exists. The timestamp is receipt time. Custom statuslines, `claude -p` and a Codex principal produce no reading.
- **Provider-limit feedback.** A job that failed with `provider_limit` in the last 30 minutes makes that provider `constrained`, evidence `provider_limit_failure_not_attributed`. The CLI classifier also matches "overloaded"/"capacity", so this reserves the provider instead of blocking it. The strictest current local signal wins; a manual decision still overrides all of them.
- **Calibration.** `quota --provider X --constrained-percent N` stores a per-provider threshold (50–99, default 90) in `policy.json`. `submit` and `retry` with a known quota append to `quota-decisions.jsonl` (last 1000 lines); `quota --provider X --report` counts decisions, refusals caused by quota, states and evidence.
- Not done here: promoting 7.23.0 to stable still needs the human pilot; showing quota in Agents Monitor belongs to that project.

## 7.23.0-rc.8 - 2026-10-18 (laboratory candidate)

- **Observed Codex quota.** `delegate.py quota --provider codex --observe` reads the latest `rate_limits` event from local Codex rollouts (`$CODEX_HOME/sessions`, bounded tail of the 20 most recent files, chosen by event timestamp rather than mtime). No credentials, no network. The reading lives in `quota-observations.json`, apart from `policy.json`, so a corrupt cache becomes `unknown` instead of blocking routing.
- Classification happens at each `route`, `submit` and `retry`, through one helper. A window at 90% or more is `constrained`, at 100% `blocked`, each until its own reset: usage only grows inside a window, so an old reading is a lower bound and a restriction stays valid. Spare capacity counts only for 30 minutes after the measurement. Jobs record `quota_evidence: local_observation_not_attributed`; the runtime accepts it alongside the manual value, so older jobs stay valid.
- A current manual snapshot other than `unknown` wins over the observation, so an explicit decision is never overridden by a fresher number. The command also prints per-window pacing (usage against elapsed window); it is informative and never enters routing.
- Limits: delegation jobs run `codex exec --ephemeral` and leave no rollout, so only interactive Codex sessions refresh the reading; the reading is explicit, not implicit in `submit`. The Claude half (statusline input `rate_limits`) was left out: it only exists with an open vault window and would need a writer outside the indicator's shared lock. The 90% threshold is a starting guess.
- Origin: idea taken from `akitaonrails/ai-usagebar` without adopting it (it reads OAuth credentials and refreshes tokens). The plan was reviewed by Astra high via the extension and Fable as a native agent with repository access; both said implement with changes, and those changes are what shipped (no pacing or 95% block in routing, per-window expiry, manual precedence, one helper for retry, cache outside policy).
